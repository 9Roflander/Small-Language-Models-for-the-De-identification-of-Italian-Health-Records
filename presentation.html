Background

The problem: GDPR de-identification of Italian clinical notes

⚖️ Why this matters

Italian hospitals share clinical notes for research, but GDPR requires all patient-identifiable information to be removed first. Manual de-identification doesn't scale — automated solutions are critical.

📋 The task

Input: raw Italian clinical note.
Output: same note with every PII span replaced inline by a placeholder tag.

Il paziente Mario Rossi, 67 anni...
↓
Il paziente [NOME], [ETÀ] anni...

Why 80 notes is a hard problem

A typical NER fine-tuning setup needs 10,000–100,000 labeled examples. We have 80 — roughly 1% of the minimum. Fine-tuning a 3B model directly on this would severely overfit.

5-fold cross-validation

64 train / 16 test per fold, all 5 folds reported. No cherry-picking. With 80 notes, CV is the only honest evaluation strategy.

Phase 2 — Iterations

How the model improved: four iterations to get it right

v0 — Wrong format

JSON extraction instead of inline redaction

Model was trained to output a JSON object with extracted entities. Fragile parsing, model never reliably emitted EOS, incompatible with the paper's evaluation metric.

0.13
v1 — Style mismatch

Switched to inline redaction, but synthetic data had wrong style

Synthetic data was generated without gold-note anchors. The model learned "synthetic-style → redact, real-style → leave alone". Gold notes read as real-style and were ignored.

0.18
v3 — Style anchoring

Gemini generation conditioned on real gold notes as style anchors

Style-anchored synthetic data fixed the style mismatch. But NOME was 4× over-represented (2.38 names/note vs 0.58 in gold), causing spurious NOME tags. High variance: one fold collapsed to 0.291.

0.535
v4 — Final

Added 475 name-free synthetic cases + doubled total synthetic volume

Fixed NOME distribution with a dedicated name-free generator. Doubled synthetic data from 878 → 1,676 samples. Variance halved, worst fold recovered from 0.291 → 0.644.

0.649
Phase 2 — Critical Finding

Why style mismatch is catastrophic

0.18
Macro-F1
style-mismatched synthetic data

Worse than the smallest zero-shot baseline (0.41). Fine-tuning made things worse.

0.649
Macro-F1
style-anchored synthetic data

Same model, same 80 gold notes, same volume of synthetic data — only generation style changed.

What happened: The model learned the spurious rule "synthetic-style text → apply redaction; real clinical text → leave alone." Gold notes looked like real text, so the model didn't touch them. The fix was anchoring every generation call on real gold note examples so the synthetic data matches the target distribution.
Key lesson: A few hundred well-styled synthetic examples outperform thousands of mis-styled ones. Style matching is more important than volume.

Summary

Three findings worth taking away

🎨

1. Synthetic data style matters more than volume

Mismatched synthetic → F1 = 0.18 (worse than zero-shot). Style-anchored synthetic → F1 = 0.649. Same model, same amount of data. The $10 spent on Gemini-anchored generation was the single biggest lever in the entire project.

⚖️

2. Entity distribution mismatch is a silent killer

4× NOME over-representation caused NOME F1 = 0.36. Adding 475 name-free cases brought it to 0.71. The fix is simple once you measure it — but invisible until you do.

📉

3. More style-matched data stabilizes, not just boosts

878 → 1,676 samples: mean F1 went from 0.535 → 0.649, but the main effect was halving variance (±0.144 → ±0.073) and rescuing the collapsed fold (0.291 → 0.644). Variance is the enemy when you only have 80 labeled notes.

Fine-tuned 3B on a 12 GB consumer GPU beats zero-shot 12B+ on Italian clinical de-identification.
Total cost: ~$15 in API calls + ~25 GPU-hours.
